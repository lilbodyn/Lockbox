# Задачі Lockbox у ЛР3

Реалізація продовжує власні правила шафки з ЛР2. Один стек MSP, без RTOS та перемикання контексту. Поточний source `484fae964f8e7cb1` використовує HAL SysTick з кроком 1 мс. Числа нижче є цілями перевірки, а не вже підтвердженими максимумами S3. Поточні результати S1/S2: [стан ЛР3](lab3-status-20261101.md).

| Задача | FR | Запуск | Дедлайн / критерій | Виконання |
|---|---|---|---|---|
| RX і команда | FR-03, FR-09, FR-10 | байти в IRQ ring, один байт за цикл | LF → завершення обробника ≤50 мс; це не час останнього байта відповіді | Grammar 32 bytes; CR ігнорується; NUL/непечатний ASCII та зіпсований рядок відхиляється до LF |
| MODE | FR-03 | кожні 1 мс | обробка release ≤5 мс; реакція після стабільного натискання ≤40 мс разом з debounce 30 мс | Утримання дає одну зміну; OFF → CALIBRATING, інші стани → OFF |
| IMU, ADC, PIR і Guard | FR-04…FR-10 | кожні 20 мс | від release до завершення ≤20 мс | I²C burst 6 bytes; ADC; незалежна PIR-подія; логіка SHOCK/LIGHT |
| Heartbeat | FR-02 | кожні 500 мс | запізнення завершення ≤5 мс | PA5; збережено окремо від PB5 ALARM |
| Телеметрія | FR-01, FR-09, FR-10 | кожні 500 мс | завершення ≤20 мс | Форматування у bounded TX ring 4096 bytes |
| Постійний архів | FR-11 | подія Guard, черга 8 подій | enqueue негайно; ціль завершення ≤1 с без перевантаження | Один doubleword або одне стирання за крок; verify, CRC, commit; відмова явна |
| Експорт RAM | FR-09, FR-10 | `journal` | до 1 с для 16 записів без потоку інших відповідей | Незмінний snapshot 16 записів, один рядок за крок лише за достатнього TX room |
| Експорт flash | FR-11 | `history` | best effort | Обхід 64 фізичних slot; ticket/boot, CRC; верхній ticket фіксується на старті, знімка flash немає |
| Вимірювання | усі часові критерії | обгортки задач, `stats` | не додає окремої продуктової гарантії | min/avg/max, jitter histogram, missed releases і deadlines, stack painting, heap peak |

Прострочені періодичні запуски не накопичуються. `release_due` рахує пропущені releases, зберігає початкову фазу і запускає один актуальний крок. Deadline miss рахується від найстарішого очікуваного release. Jitter є фактичним міжстартовим інтервалом мінус період. Histogram абсолютного jitter має межі 10, 100, 1000, 5000, 20000 мкс.

`sample 10/5/2/1` є діагностичним підвищенням навантаження. Кількість точок фільтрів Guard залишається сталою; часовий зміст калібрування й світлового вікна у цих режимах відрізняється від PRD. Продуктове приймання виконується лише за `sample 20`. Повернутися до 20 мс потрібно перед S1/S2/S3.

IRQ використовуються для USART2 RX, timestamp EXTI PA1/PA10 і SysTick HAL. TIM3 overflow IRQ вимкнено; foreground та SysTick накопичують uint16 різниці CNT під PRIMASK. Між читаннями потрібно строго менше 65.536 мс; max_modulo_step не доводить цю межу. TX має polling одного готового байта за цикл. `volatile` не робить flush/pop RX атомарним: foreground pop і timestamp захищені PRIMASK. Після помилки ISR очищає чергу та відкидає потік до LF. EXTI зберігає останню мітку каналу, не чергу всіх фронтів; короткі/часті події можуть об'єднатися.

`stats` форматує кілька рядків синхронно і сам навантажує цикл. Його час входить до наступного вікна статистики. Це окремий діагностичний вплив, який треба показувати, а не приховувати.

Uptime Guard накопичується з unsigned різниць TIM3 через `uptime_update`; `stats reset` його не скидає. Це зберігає мілісекундний uptime через 32-bit microsecond wrap і не покладається на кількість SysTick ISR після flash stall. HAL tick лишається часовою базою vendor HAL. I²C register wait має timeout10000 мкс за TIM3. Це ще не підтверджено реальним flash stall.
